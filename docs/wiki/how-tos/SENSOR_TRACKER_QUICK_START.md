# Sensor Tracker Integration - Quick Start Guide

## Overview
This guide will help you get started with integrating Sensor Tracker data into the Wave Glider Buddy System.

## Prerequisites
1. Access to Sensor Tracker instance
2. Authentication credentials (token or username/password)

## Setup Steps

### 1. Install Dependencies
The `sensor_tracker_client` library has been added to `requirements.txt`. Install it:

```bash
pip install -r requirements.txt
```

Or install directly:
```bash
pip install git+https://gitlab.oceantrack.org/ceotr/metadata-tracker/sensor_tracker_client.git
```

### 2. Configure Sensor Tracker Connection
Add these settings to your `.env` file:

```env
# Sensor Tracker Configuration
sensor_tracker_host=http://bugs.ocean.dal.ca/sensor_tracker/
sensor_tracker_token=your_token_here
# OR use username/password:
# sensor_tracker_username=your_username
# sensor_tracker_password=your_password

# Optional: Enable debug mode (points to localhost)
# sensor_tracker_debug=False
# sensor_tracker_debug_host=http://127.0.0.1:8000/
```

**Note**: You can use either `sensor_tracker_token` OR `sensor_tracker_username`/`sensor_tracker_password`, but not both.

### 3. Test the Connection
Use the test script to verify your connection and fetch a deployment:

```bash
python scripts/test_sensor_tracker.py <deployment_id>
```

Example:
```bash
python scripts/test_sensor_tracker.py 123
```

This will:
- Test the Sensor Tracker connection
- Fetch the deployment data
- Parse it into a structured format
- Save both raw and parsed JSON files to `test_data/`

### 4. Inspect the Data
After running the test script, check the generated JSON files:
- `test_data/sensor_tracker_deployment_<id>_raw.json` - Raw data from Sensor Tracker
- `test_data/sensor_tracker_deployment_<id>_parsed.json` - Parsed structure

Use these files to understand the actual data structure and refine the parser.

## Understanding the Data Structure

### Deployment Components
A deployment in Sensor Tracker contains:

1. **Regular Fields**: Basic metadata (lat/lon, dates, etc.)
2. **Platform**: The physical platform
   - Instrument on Platform History
   - Data Logger (flight or science)
     - Flight: Instrument on Data Logger History, parameters
     - Science: Instrument on Data Logger History, Data Logger on Platform History, parameters
   - Custom Fields
3. **Instrument on Platform History**: All/Now/On Date options
4. **Sensor on Instrument History**: All/Now/On Date options
5. **Images**: Deployment images
6. **Custom Fields**: Additional custom metadata

### History Options
When fetching history data, you can choose:
- **All**: All historical records
- **Now**: Current state only
- **On Date**: State at a specific date

## Troubleshooting

### Import Error: sensor_tracker_client not found
```bash
pip install git+https://gitlab.oceantrack.org/ceotr/metadata-tracker/sensor_tracker_client.git
```

### Authentication Error
- Verify your token or username/password in `.env`
- Check that the Sensor Tracker host URL is correct
- Ensure your credentials have appropriate permissions

### Connection Timeout
- Verify network connectivity to Sensor Tracker host
- Check firewall settings
- Try enabling debug mode to test against localhost

### Data Structure Issues
- Inspect the raw JSON files generated by the test script
- Compare with Sensor Tracker API documentation
- Update the parser in `app/services/sensor_tracker_service.py` as needed
